# 资料与既有接口约定

对象使用AESGCM认证加密，AAD为规范JSON的tenant和object_id。每对象随机256位数据密钥，key_service.py 使用另一个AESGCM主密钥包装，包装AAD还含tenant、object_id及数据正文摘要。主密钥只在服务实例内存及未跟踪的运行目录存在；公开资料仅含非秘密key_id。rotate不改变正文密文、nonce与AAD，只生成新的wrapped_key。服务支持按操作ID返回相同回执和可控故障。现有 envelope.py 只实现单对象首次封装和读回。

所有资料均为合成，字段、身份及状态按本文解释。源码中的 inspect 入口只读取并核对现有基础接口；不会建立高级查询或仓库管理流程。

## 密钥轮换管理（新增）

`warehouse/rotation.py` 在既有的 `envelope.py`、`catalog.py`、`key_service.py` 之上提供可续作的轮换，不改变正文密文、nonce 或 AAD：

- **不可变正文**：`rotate` 只重做 `wrapped_key` 及其 nonce，`body`/`nonce` 原样保留；检查点与目录版本都只存包装后的信封。
- **提交边界**：`main` 目录在轮换期间始终指向旧版本。`complete()` 先把新版本写进对象仓并逐对象重新解开、核对租户/摘要/包装上下文，再用一次锁内的比较更新同时登记旧版本保留引用和切换 `main`。任何一步失败都保持旧头，检查点可继续。
- **可续作**：每个对象替换成功后检查点原子落盘；`begin()` 可恢复未完成的检查点，`resume()` 只处理未核验对象。密钥服务的操作 ID 由检查点前缀与对象身份确定性生成，`fail_at`（副作用前失联）与 `fail_after_at`（已记账但回执丢失）都能续作，已核验的包装不会二次替换。
- **归属校验**：读取在调用密钥服务前显式核对 `tenant`、`object_id`、`body` 与包装上下文；解密成功本身不构成租户归属证明，跨租户或复制元数据会先被拒绝。
- **旧读者**：`Reader` 钉住版本摘要；`pinned_snapshot()` 建立的快照登记为 `snapshot:<摘要>` 目录引用，`snapshot_reader()` 据此解包创建时的版本。保留引用未释放时不会消失。
- **退休判断**：`audit(key_id)` 在目录锁内遍历所有引用（当前头、保留版本、钉住快照），并计入未发布检查点里的旧/新包装；只有全部引用都不再使用该主密钥、且密钥服务返回停用回执后才写退休记录。该记录注明 `physical_deletion: false`：本地服务停用不代表任何备份或快照副本已物理销毁。
